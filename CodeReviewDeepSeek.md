## 1. Задача 1, пункт 2 — CWordShuffler

### Сильные стороны
- Логика вынесена в отдельный класс `CWordShuffler`, `main.cpp` содержит только ввод/вывод.
- Используется `std::wstring`, поэтому кириллица не ломается при перестановке.
- `std::mt19937` инициализируется через `std::random_device`, перестановки разные при каждом запуске.
- Счётчик включает финальную перестановку, совпавшую с исходным словом, как в примере задания.
- XML-документация присутствует.
- Нет `auto`, `NULL`, C-style cast; фигурные скобки всегда.

### Замечания
1. **Пустое слово.** Обрабатывается исключением — лучше, чем зацикливание.
2. **Слово из одного символа.** Цикл завершится за одну попытку, это корректно.
3. **Локаль и кириллица.** `std::locale("")` ведёт себя по-разному на Windows/Linux; на Windows может потребоваться `SetConsoleOutputCP(CP_UTF8)`.
4. **Длинные слова.** Ожидание совпадения может быть долгим — свойство самой задачи, не ошибка.

### Соответствие code style
- Класс `CWordShuffler` — префикс `C`. ✅
- Приватное поле `_Engine`. ✅
- PascalCase, `nullptr`, фигурные скобки. ✅
- XML-документация. ✅

## 2. Задача 2 — CalcTree6

### Сильные стороны
- Логика вынесена в класс `CExpressionTree`.
- Поддержаны все операции задания: `+`, `-`, `*`, `/`, `%`, `^`.
- Коды операций соответствуют заданию: -1, -2, -3, -4, -5, -6.
- `TransformPowerSubtreesToValues` заменяет поддеревья, содержащие `^`, на вычисленное значение — ровно по заданию.
- Разбор префиксной записи корректен для одиночных цифр и операций без обязательных пробелов.
- Проверки деления на ноль, остатка от деления на ноль, отрицательного показателя степени.
- `BuildFromPrefixFile` очищает предыдущее дерево.
- `PrintRootPointer` печатает адрес корня через `static_cast<const void*>`.
- XML-документация присутствует.

### Замечания
1. **Утечки памяти при исключениях в `_ParsePrefix`.**  
   Если рекурсивный вызов для левого или правого ребёнка выбросит исключение, уже созданный узел `Node` может остаться не удалённым.  
   Рекомендация: `std::unique_ptr<SExpressionNode>` для временного владения.

2. **Утечки памяти в `_TransformNode`.**  
   Если `_EvaluateNode` выбросит исключение, узел `Node` не будет удалён.  
   Рекомендация: RAII или `try/catch` с освобождением.

3. **Целочисленное возведение в степень.**  
   `_IntegerPower` через цикл корректен для неотрицательных показателей. Отрицательный показатель отбрасывается исключением, что для задания допустимо, но не описано в задании — стоит упомянуть в отчёте.

4. **Смешение ответственности.**  
   `CExpressionTree` одновременно парсит, хранит, трансформирует и печатает дерево. Для лабораторной допустимо, но в production лучше разделить парсер, трансформер и вывод.

5. **Переполнение `int`.**  
   При больших показателях `^` возможно переполнение. В задании операнды 0-9, но для надёжности можно ограничить показатель или использовать `long long`.

### Соответствие code style
- Класс `CExpressionTree` — префикс `C`. ✅
- Структура `SExpressionNode` — префикс `S`. ✅
- Приватные методы с `_`. ✅
- PascalCase, `nullptr`, фигурные скобки. ✅
- XML-документация. ✅

## 3. Задача 3 — Graf5

### Сильные стороны
- Логика графа вынесена в класс `CGraphAnalyzer`.
- BFS оптимален для поиска достижимости по числу рёбер.
- Результат сортируется по возрастанию номеров городов.
- Если городов нет, выводится `-1`.
- Нумерация городов переводится из 1-based в 0-based.
- XML-документация присутствует.

### Замечания
1. **Трактовка «менее чем с L пересадками».**  
   В реализации: пересадок = число рёбер − 1, поэтому «меньше L пересадок» = путь длиной не более `L` рёбер. Это задокументировано в XML-комментарии. Если преподаватель трактует иначе, нужно изменить условие `NewDistance > MaxTransfers`.

2. **Нет валидации значений матрицы.**  
   Предполагается, что матрица содержит только `0` и `1`. Рекомендуется проверять `Value == 0 || Value == 1`.

3. **Симметричность матрицы не проверяется.**  
   Для неориентированного графа матрица должна быть симметричной. Для учебной задачи допустимо.

4. **Петли не влияют на результат.**  
   При `m[i][i] = 1` стартовый город не попадает в список, так как `Distance[StartIndex]` уже установлен. Это соответствует заданию.

5. **Отрицательное `L`.**  
   Возвращается пустой вектор, в `main` выводится `-1`. Стоит явно указать в документации.

### Соответствие code style
- Класс `CGraphAnalyzer` — префикс `C`. ✅
- Приватные поля `_AdjacencyMatrix`, `_CityCount`. ✅
- PascalCase, `nullptr`, фигурные скобки. ✅
- XML-документация. ✅

## 4. `main.cpp` для каждой задачи

### Сильные стороны
- Каждый `main.cpp` относится только к одной задаче.
- Общего меню нет, задачи независимы.
- Обработка исключений через `try/catch`.
- Нет `using namespace std`.
- Для графа выводится `-1`, если список пуст.
- Для CalcTree6 выводятся исходное дерево, значение, преобразованное дерево и указатель на корень.

### Замечания
1. **Нет проверки корректности ввода чисел.**  
   Если пользователь введёт не число, `std::cin` перейдёт в состояние ошибки. Для лабораторной достаточно, но можно добавить `if (!std::cin)`.

2. **Сообщения на английском.**  
   Это соответствует code style для кода и комментариев. Если требуется русский интерфейс, строки можно локализовать.

## Итог
Код соответствует варианту 5 и приложенному C++ code style. Каждая задача оформлена отдельным набором файлов.

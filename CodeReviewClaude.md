## 1. Задача 1 — CWordShuffler

### Сильные стороны
- Логика вынесена в отдельный класс `CWordShuffler`, `main.cpp` содержит только ввод/вывод.
- Разбиение UTF-8 на code points реализовано через битовую маску `10xxxxxx`: кириллица и другие многобайтовые буквы не разрезаются при перестановке.
- `std::mt19937` инициализируется через `std::random_device`, перестановки разные при каждом запуске.
- Счётчик включает финальную перестановку, совпавшую с исходным словом.
- Ограничение `MaxLetterCount = 8` защищает от факториального роста ожидаемого числа попыток.
- Пустое слово корректно возвращает `0` без вывода.
- XML-документация присутствует.
- Нет `auto`, `NULL`, C-style cast; фигурные скобки всегда.

### Замечания
1. **Нет проверки состояния `_Output`.** Если поток вышел из строя (например, диск заполнен), цикл продолжит крутиться. Стоит проверять `_Output.good()` в цикле или явно задокументировать, что ошибки вывода игнорируются.
2. **Нет верхней границы итераций.** Практически с `mt19937` зацикливание невозможно, но защитный предел (например, `1000 * N!`) сделал бы поведение предсказуемым.
3. **Слова с повторяющимися буквами.** Для слова вроде `"aaa"` первая же перестановка совпадёт с исходной, и цикл завершится за одну итерацию. Это корректно по постановке, но стоит упомянуть в XML-комментарии.
4. **Невалидный UTF-8.** `_SplitIntoLetters` для ведущего continuation-байта создаст «букву» из одного байта. Для ввода из `std::cin` это маловероятно, но в документации стоит указать, что функция ожидает валидный UTF-8.
5. **`RandomEngine(std::random_device()())`** приемлемо; на некоторых платформах `random_device` может быть детерминированным, но для учебной задачи это не критично.

### Соответствие code style
- Класс `CWordShuffler` — префикс `C`. ✅
- Приватное поле `RandomEngine`. ✅
- PascalCase, `nullptr`, фигурные скобки. ✅
- XML-документация. ✅

## 2. Задача 2 — CExpressionTree

### Сильные стороны
- Логика вынесена в класс `CExpressionTree`, узлы — `SNode` с `std::unique_ptr` на детей.
- Поддержаны все операции задания: `+`, `-`, `*`, `/`, `%`, `^`.
- Коды операций соответствуют заданию: -1, -2, -3, -4, -5, -6 (`EOperation`).
- `RemovePowerOperations` заменяет поддеревья, содержащие `^`, на вычисленное значение — ровно по заданию.
- Разбор префиксной записи корректен для одиночных цифр и операций без обязательных пробелов; `BuildFromPrefix` даёт строгую гарантию безопасности исключений (новое дерево строится локально и присваивается только в конце).
- Проверка «лист/внутренний узел» везде идёт по детям, а не по знаку `Data` — это важно после свёртки степеней, когда лист может содержать отрицательное значение.
- `IntegerPower` аккуратно обрабатывает `Base ∈ {0, 1, -1}`, отрицательные показатели и переполнение через `ToCheckedInt`.
- Деление и остаток вычисляются в `long long`, поэтому `INT_MIN / -1` и `INT_MIN % -1` не приводят к UB.
- `ToPrefixString` печатает префиксную запись для диагностики.
- XML-документация присутствует.

### Замечания
1. **Частичная модификация при исключении.** Если `Evaluate` бросит `domain_error` или `overflow_error` на очередной степени, ранее уже свёрнутые степени останутся заменёнными листьями. Дерево останется валидным, но `RemovePowerOperations` не атомарна. Стоит либо задокументировать это в `CExpressionTree.h`, либо сначала вычислить все значения, а потом применять замены.
2. **Отрицательный показатель степени.** `IntegerPower` возвращает `0` при отрицательном показателе (кроме случаев `Base ∈ {0, 1, -1}`), что для задания допустимо, но не описано в постановке — стоит упомянуть в отчёте.
3. **Смешение ответственности.** `CExpressionTree` одновременно парсит, хранит, трансформирует и печатает дерево. Для лабораторной допустимо, но в production лучше разделить парсер, трансформер и вывод.
4. **`CreateLeaf`** можно пометить `noexcept`.
5. **`AppendPrefix`.** Разделитель ставится по `!_Result.empty()`. Логика верна, но читается неочевидно; можно вынести флаг «первый токен».

### Соответствие code style
- Класс `CExpressionTree` — префикс `C`. ✅
- Структура `SNode` — префикс `S`. ✅
- Enum `EOperation` — префикс `E`. ✅
- Приватные методы с `_`. ✅
- PascalCase, `nullptr`, фигурные скобки. ✅
- XML-документация. ✅

## 3. Задача 3 — CAirRouteGraph

### Сильные стороны
- Логика графа вынесена в класс `CAirRouteGraph`.
- BFS оптимален для поиска достижимости по числу рёбер.
- Результат формируется по возрастанию номеров городов (итерация по `CityIndex`).
- Если городов нет, `main.cpp` выводит `-1`.
- Нумерация городов переводится из 1-based в 0-based.
- `LoadFromFile` валидирует `n ∈ [1, 25]` и значения матрицы `∈ {0, 1}`; новые данные применяются только после успешного чтения — при ошибке старое состояние графа сохраняется.
- Проверка `_StartCity` на диапазон присутствует.
- XML-документация присутствует.

### Замечания
1. **Нет проверки «хвоста» файла.** После чтения матрицы не проверяется, остались ли в файле лишние числа. Стоит добавить:
   ```cpp
   int Extra;
   if (Input >> Extra) {
       throw std::invalid_argument("Unexpected data after matrix.");
   }
